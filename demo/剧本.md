# 万历新政：剧本

演示案例的剧情和每一回演示什么。**全部是虚拟数据**：事件按剧情在固定的模拟时间里生成，不真实派活、不调用模型；事件走 `core/flow.py` 的真实写入路径，所以流转规则、检查、生成块、视图模型和看板都和真实使用时一样。取材于万历初年（潘季驯治河、张居正清丈与一条鞭法、隆庆和议后的俺答互市、月港开海），时间线压缩、细节虚构，不作史实考据。

## 角色

| 系统席位 | 剧中身份 | 现实中扮演它的应用 |
|---|---|---|
| 总裁 | 陛下（你），朱笔批红 | 用户 |
| 总管 | 内阁首辅：票拟、调度部院 | Claude Desktop |
| 成员 | 工部：河工、营造 | Codex |
| 成员 | 户部：钱粮、清丈 | DeepSeek |
| 成员 | 兵部：边务、互市 | Codex（另一型号） |
| 成员 | 都察院：巡按核验、科道封驳 | Claude 命令行 |
| 成员 | 翰林院：拟诏 | Claude 命令行 |

看板用一套称谓把系统用语换成明朝叫法（只换显示，不改数据）：待你决定 → 待批红，总管建议 → 内阁票拟，上报 → 奏报，确认 → 核验，越过 / 偏离 → 逾制，派发 → 交办，交付 → 复命，目标 → 国事，任务 → 差事，阶段 → 节次。对照表在 `build.py` 的 `TITLES`。

## 四件国事

| 编号 | 国事 | 类型 | 节次 | 部院 |
|---|---|---|---|---|
| G001 | 黄河决口：赈灾与治河 | 开发 | 方略 → 施工（堵口、钱粮并行）；赈济与之同时起 → 验收 | 工部、户部、翰林院；都察院验收 |
| G002 | 清丈田亩与一条鞭法试点 | 调研 | 清丈（山东、江南并行）→ 试点 → 验收 | 户部（后添工部）；都察院验收 |
| G003 | 北边：俺答求贡互市 | 通用 | 钱粮核定 → 互市谈判 | 户部、兵部 |
| G004 | 月港开海调研 | 调研 | 检索 → 综合成文 | 户部 |

G001 立案后先经「讨论」「方案」两个起草阶段（`起草阶段` 事件，目录里有 `问题.md`、`方案.md`），再搭框架进呈。每件差事都属于国事，没有零散差事。G001 的赈济节次里有两件：G001-T4 拟赈灾诏（陛下亲交翰林院，四易其稿），G001-T6 河南报灾（记错后勘误，再撤销）。三次廷议是黑板事件（`流转/I00x.jsonl`），和真实朝会同一条写入路径，看板朝会页里能逐条看：I001 治河方略之争（挂 G001，陛下点名户部）、I002 清丈框架会审（挂 G002，都察院点名户部，随批红一起裁决）、I003 和战之议（挂 G003，都察院私下进言）。决议 D001–D003。

## 回目

每一回都可以单独生成：`python3 demo/build.py --到 N`，项目停在这一回结束的时刻（时钟写在 `collab/流程/时钟.json`）。

### 第一回　河决徐州　内阁票拟（三月初一至初五）
- 内阁立案 G001，进呈的节次（方略 → 施工，赈济同时起）和「开发」模板不同；差事进呈前都已拟好，陛下批红并加都察院验收（第三方验收节次自动追加）。
- 赈济节次：陛下亲交翰林院拟赈灾诏（G001-T4），**四易其稿**才准颁行：总裁直接派活、直接核验，需补充不计返工次数。
- 工部呈治河方略，开廷议 I001（束水攻沙 vs 分流），定 D001；内阁核验方略。
- 施工节次两路并行：户部核钱粮，工部开工堵口。
- **看点**：立案 → 进呈 → 批红的目标流转；节次并行；廷议引出决议。

### 第二回　清丈议起　阁臣会审（三月初五至初八）
- 立案 G002，开框架会审 I002：都察院反对「清丈全凭地方上报」，坚持加独立核验，户部同意；陛下依会审批红并加都察院验收。**多模型会审改变了框架**。
- 户部两省并行清丈；江南第一轮只开了个头没写结束边，派活脚本代写「奏报：未声明结果」，内阁准其续丈。
- 通政司转来的河南报灾（G001-T6）记错了，用「勘误」作废。
- **看点**：框架会审；派活脚本的兜底；更正。

### 第三回　堵口缺银　待批内帑（三月初九至十一）
- 工部奏报缺银十万两，内阁无从挪借，转呈陛下，附票拟 A 拨内帑 / B 加派民夫 / C 待秋汛，建议 A。
- 河南报灾差事（G001-T6）撤销，灾情由钱粮差事一并核。
- **停在这一回**：「待批红」里有一道奏本，等你朱批。

### 第四回　朕批内帑　江南阻丈（三月十二至十五）
- 陛下准拨内帑，工部续工；奏本自动从「待批红」消失。
- 户部奏报苏松豪强匿田阻丈，内阁转呈陛下：遣钦差 / 暂缓江南。
- **停在这一回**：又一道授权类奏本等你朱批。

### 第五回　北虏求市　廷议和战（三月十六至二十四）
- 立案 G003、G004。开海初次进呈「全开海禁」被陛下**留中**（退回），改票「限船引」再进呈才批红；随即进行中的国事已有四件，内阁奏请开海暂缓（暂停）。
- 陛下遣钦差督丈苏松。
- 户部核边饷这一轮没写结束边，又被派活脚本代写奏报。
- 陛下特许兵部在边饷未定时先行接洽：派发越过节次顺序，看板标「逾制」。
- 决口合龙；开廷议 I003 和战之议，都察院持异议并要求原文存档，陛下裁决附条件开市（D002）。
- **看点**：退回；负载过重时暂停；逾制；廷议保留异议。

### 第六回　河工告成　巡按核验（三月二十五至四月初二）
- 都察院巡按核验河工；内阁奏告成，陛下结案 G001。
- 江南清丈毕、山东试点毕；兵部互市章程漏了 D002 的违约闭市之条，被核验退回补正。
- 河工已结，开海恢复，差事建好。
- 都察院开始核验清丈。
- **看点**：第三方验收节次；告成 → 结案；恢复。

### 第七回　鱼鳞册伪　清丈重开（四月初三至十一）
- 都察院核验发现苏松三县鱼鳞册雷同、疑为抄改。内阁**重议**江南清丈：清丈节次回到进行中，试点、验收两个节次的通过**自动失效**。陛下准改成功标准（误差须在百分之一以内），记为要批准的更张。
- 户部复丈连返两次仍超差，返工到上限，核验判未通过；内阁先在框架内给清丈节次添工部，再**改委**工部协办，复丈合格。
- 都察院重新核验，内阁奏清丈告成。
- **停在这一回**：「待批红」里是清丈结案。
- **看点**：证据推翻前提 → 重开 → 后续节次自动失效；返工上限 → 升档改委；要批准的更张。

### 终回　朱批定案　新政初成（四月十二至十八）
- 陛下结案 G002，一条鞭法先行山东（D003）。
- 互市告成被陛下**驳回**一次：章程须载都察院异议与复核之期；补正后再告成，结案。
- 开海检索毕；综合成文节次添兵部、工部、都察院分头办（框架内换人）。户部利弊疏初稿径送翰林院核验；兵部因浙闽塘报未到奏报受阻；工部福船料价超估一倍，内阁转呈陛下（待批红）；都察院密访月港私贩，派活还在跑。
- **看点**：打回；结局停在「正在办」的一刻：三件结案、开海五路在办；G004 关系图同时有成员之间的交接（户部 → 翰林院）、奏报受阻、转呈陛下和在跑的派活。

## 覆盖情况

终回时事件里出现过的边：建立、提交、退回、批准、派发、接手、交付、确认（通过 / 需补充 / 未通过）、转交、上报、解除、改派、重开、暂停、恢复、取消、目标验收、打回、完成，以及变更、进展、更正。另外演示了：派活脚本兜底奏报、越过（逾制）、第三方验收节次、节次并行、阶段失效、跨目标依赖（G003 依赖 G002）、待批红的产生和消失、长间隔折断、执行中久无事件的提醒。

## 改剧本

剧情都在 `build.py` 的 `ch1`–`ch8`。改了剧情或改了流转规则后：

1. `python3 demo/build.py` 重新生成，确认不报错（剧本本身也要过 flow 的检查，写错了会被拒）。
2. `python3 -m unittest tools.tests.test_demo` 会报出哪一回的视图模型变了；确认是预期的变化后，`UPDATE_GOLDEN=1` 重跑一次更新期望文件。
