# core：流转引擎

工具包的核心都在这里，只用 Python 标准库和 bash：

| 文件 | 做什么 |
|---|---|
| `flow.py` | 流转的唯一写入口和投影：骨架、事件、检查、生成块、视图模型、上下文包 |
| `check.py` | collab/ 校验：派活前、Claude 每轮结束（Stop hook）、看板顶部都用它 |
| `collab_parse.py` | 任务卡、目标卡解析（旧结构项目和卡片手写字段） |
| `dispatch.py` | 派活：向命令行成员派活、续接、停止、朝会，写运行记录（下文） |
| `init.sh`、`team.py`、`now_rows.py`、`modules.py` | 给项目装工作台、建 NOW、建班子、team-sync、装 hook、在 NOW 注册 / 注销项目、管理看板模块、合并口令（下文「init.sh」） |
| `口令.md` | 核心的口令；`init.sh rules` 把它和已启用模块的口令合并成 `NOW/口令.md` |
| `publish.sh` | 把已提交的工具包发布到本机 `NOW/系统/`；`--core <目标>` 只带核心，`--module <id> <目标>` 单独导出一个模块 |

想法、讨论、方案：每个想法先建目标卡（`flow.py 建立 目标 --标题 … --依据 …`，类型默认通用）。起草状态的卡有阶段（想法、讨论、方案，默认想法），由 `flow.py 记 G00x 起草阶段 --结果 讨论` 这类事件回放得出，显示在卡头和视图模型 `目标.起草阶段`；已有目标没有这类事件的照常显示。文档放在 `collab/目标/G00x/`：`问题.md`（待解决、已解决）、`方案.md` 和其他 Markdown（`目标.文件` 给路径，`目标.待解决` 给问题），旧卡的 `讨论.md` 照常识别；上下文包只给方案路径、不带问题。新目标卡只有「要什么」「成功标准」。PROGRESS 的目标表不逐行列起草中的目标，只汇总一行（想法 n 个｜讨论中｜方案中）。`flow.py 归档 G00x` 把完成或取消的目标卡和 `目标/G00x/` 一起移到 `归档/目标/`；只移了卡片没移目录时，`flow.py 检查` 报错。起草中的目标可以暂停、恢复。

看图批准：`flow.py 框架 G00x --文件 框架.json` 一次写好阶段和全部任务卡（规划中），可重复运行，自动记下这轮改了什么；目标批准时任务一起转为已批准并存批准版。视图模型给出 `目标.结构`（按阶段、任务、派发交付确认排，计划和实际同位）、`目标.差别`（和批准版比）、`目标.本轮改动`、`目标.意见`。总裁反馈可视化：事件行带「依据」，非默认依据（不是框架自动写的「<目标> 框架」）标 `原话`，页面把原话和总管的说明分开显示；批准后新增的任务若建立依据是原话，`结构` 在派发前加一步 `要求`（总裁 → 总管，事件行带 `画` 让页面按总裁画），总管自己补的卡不画；总裁的退回、打回和同依据的新增任务互相带 `催生` / `来自`；目标层总裁的打回和带依据的变更放进 `目标.结构.反馈`。看板批准带批注（依据「总裁在看板批准第 N 版框架：批注」）时，批注进 `目标.意见`，同样出现在 PROGRESS「待你决定」和看板，直到总管在这个目标上记一条进展（`flow.py 记 G00x 进展 --作为 总管 --说明 "已处理批注：…"`）；不带批注的批准不出现；目标完成或取消后不再提示。任务必须归属目标；规划中不能开工，不能越过。方案见开发仓库 `collab/归档/文档/看图批准.md`。

开发版保护：没有 `版本.txt` 的工具包（即开发仓库的 `src/`）拒绝写自己所在仓库的账本和 `workbench/` 模板（`flow.py` 的写入和 `dispatch.py` 除 `list`、`show` 外的命令）；发布版、`demo/`、其他项目不受影响。
| `skeletons/` | 流程骨架：`task`、`goal`（`goal-general` / `goal-research` / `goal-dev` 三种阶段模板）、`issue`，加载清单 `loading`，渲染规约 `render`；`history/` 放旧版本。事件和项目覆盖仍用中文骨架名（任务、目标、议题……），`flow.py` 的 `SKEL_FILES` 负责对应 |

# init.sh：工作台、NOW、班子

**工作台**是 `../workbench/` 里那一套：装进项目后，项目根目录只多一个 `AGENTS.md`（Claude Code 通过 `.claude/CLAUDE.md` 的 `@../AGENTS.md` 导入；根目录已有 `CLAUDE.md` 时改为在其中追加 `@AGENTS.md`），协作文件全部在 `collab/` 下，`collab/PROGRESS.md` 是总管唯一的入口。

```
项目/
  AGENTS.md          唯一露在根目录的协作文件
  .claude/CLAUDE.md  @../AGENTS.md
  .gitignore         加一行 .scratch/（成员草稿不进 git）
  collab/            PROGRESS、协议、成员、决议、经验、日志、目标/、任务/、议题/、内部/（流转、流程、运行记录，工具自己用的，不手改）、产出/、归档/
  work/              交付和草稿：一个目标一个工作目录 G001-<标题>/（目标批准时才建，起草阶段不留空目录）；
                     交付放 <工作目录>/<任务>/，成员草稿放 <工作目录>/.scratch/<成员>/<任务>/
```

四层分开：工具包（本目录）、班子（`NOW/班子/`）、项目文件（真正的工作和交付）、`collab/`（管理账本：流转、卡片、议题、决议、日志、运行记录）。`collab/` 进驻后终身跟着项目；项目归档时整个文件夹一起打包，`unregister` 从 NOW 注销；重启时 `register` 重新注册，工作台照旧。详见协议「工作区」。

| 命令 | 作用 |
|---|---|
| `new [目录] [-n 项目名] [--no-now]` | 给项目装工作台；目录默认当前目录，项目名默认目录名。按班子生成 `collab/成员.md`，装 Stop hook，`.gitignore` 加 `.scratch/`，并在 NOW 任务表加一行（`NOW_PATH` 指向 `NOW.md`，默认 `~/Desktop/NOW.md`；`--no-now` 不加）。已有 `collab/PROGRESS.md` 时不做任何改动 |
| `register [目录] [-n 项目名]` | 把已有工作台的项目加回 NOW 任务表（状态进行中）；在 `NOW/已完成.md` 里的移回来，保留名称和分类 |
| `unregister [目录] [-m 一句话结果] [--drop]` | 从 NOW 任务表移到 `NOW/已完成.md`（补今天的日期和结果）；`--drop` 直接删去。项目文件和 `collab/` 不动 |
| `protocol [目录]` | 用最新工作台更新 `collab/协议.md`（保留末尾「本项目补充」一节）、各 `_模板.md` 和 PROGRESS「加载地图」；PROGRESS 其余内容不动 |
| `tidy [目录] [--all]` | 把旧位置的 `collab/流转`、`流程`、`运行记录` 搬进 `collab/内部/`；两边都有内容时不动，提示手动合并。`--all` 处理 NOW 任务表里的全部项目 |
| `hook [目录]` | 给已有项目装 Stop hook（写进 `.claude/settings.json`）：每轮结束运行 `core/check.py --hook`，校验有错就不让这一轮结束 |
| `now [目录]` | 建立 NOW 总看板，见 [board/now/README.md](../board/now/README.md) |
| `team [班子目录]` | 从 `team-example/班子.json` 建立班子配置 |
| `team-sync [目录] [--all] [--force]` | 按班子配置重新生成 `collab/成员.md`；`--all` 刷 NOW 任务表里的全部项目；不是生成的文件要加 `--force`（原文件备份为 `成员.md.bak`） |
| `module list / enable <id> / disable <id> / init <id> [--now-dir 目录]` | 管理看板模块，见 [modules/README.md](../modules/README.md)；`enable`、`disable` 会重新合并口令 |
| `rules [--now-dir 目录]` | 把核心和已启用模块的口令合并成 NOW 数据目录下的 `口令.md` |

**班子**：你的成员（应用、型号、档位、成本、命令、权限）只写一次，在班子目录的 `班子.json`。班子目录取环境变量 `COLLAB_TEAM`；没设时用工具包旁边的 `班子/`（本机即 `NOW/班子/`）；都没有时 `~/.collab-team`。生成的 `成员.md` 顶部有标记，除末尾「## 本项目补充」外不要手改，刷新时保留那一节。

**稳定性**：除 `protocol` 外从不覆盖已有文件；已有的 `AGENTS.md` / `CLAUDE.md` 只追加入口说明，重复运行不会重复追加；`team-sync` 只改 `collab/成员.md`。

# 派活

总管（Claude 桌面版）用它向命令行成员派活、续接、停止，并把每次派活写进项目的 `collab/内部/运行记录/`。看板从那里读取实时进度。只用 Python 标准库；任务卡和目标卡的解析在 `core/collab_parse.py`，与看板共用。

## 用法

在项目目录或其子目录里运行（脚本向上找 `collab/PROGRESS.md` 认项目），或加 `--project <目录>`：

```sh
python3 core/dispatch.py start T003 执行 codex "执行 T003：读 collab/PROGRESS.md 和 collab/任务.md 中这张卡，按卡执行。"
```

```sh
python3 core/dispatch.py continue T003 执行 "返工：……"
```

```sh
python3 core/dispatch.py stop --all
```

| 命令 | 作用 |
|---|---|
| `start <任务> <席位> <成员> <启动语>` | 开新会话派活（可加 `--override` / `--adhoc` / `--skip-check`，见下节） |
| `continue <任务> <席位> <启动语> [--run 编号]` | 续接该任务该席位最近一次的会话（或指定派活的会话）；成员沿用那一次的 |
| `stop <编号>` / `stop --all` | 停止一次 / 本项目全部正在跑的派活，状态记为「已中断」，会话保留可续接 |
| `list [--all]` | 列出派活：运行中的全部，加最近 10 条（`--all` 全部） |
| `show <编号>` | 显示一次派活的启动语、会话、token 明细、最终回复 |
| `tokens [--force]` | 从原始事件补算各次派活的 token（默认只补还没有的；新派活会自动记，一般不用） |
| `meet <议题> [--wake 成员 …] [--detach]` | 朝会：新结构项目叫醒与会者、只喂增量，发言写回黑板；旧结构项目 `[--round N]` 开下一轮（见下节） |

- 启动语写 `-` 时从标准输入读。
- 派活、续接和朝会前过三道关（见下节）；不过就不派，退出码 2。
- 命令在成员结束时才退出，退出码 0 为完成、1 为失败、130 为被停止。总管以后台命令运行它，结束时自动被唤醒，输出末尾是最终回复。
- 成员在项目根目录运行。
- 席位是自由文字，常用「执行」「验收」。同一任务里，续接按「任务 + 席位」找会话，所以执行和验收各有各的会话。

## 新结构项目（有 `collab/内部/流转/`）

流转由 [`core/flow.py`](../core/flow.py) 记成事件，派活脚本经它代写，不再按 Markdown 流转表检查：

- **派活前**：先跑第 1 关校验（新结构项目即 `flow.py 检查`）；然后经 flow 写「派发」「接手」（确认席位写「转交」给该成员，续接写「进展」）。顺序、人选、目标是否批准由 flow 判断，不合法就不派；确需偏离加 `--override "理由"`，记成事件的「越过」。
- **启动语**：你写的启动语只说这次做什么，脚本在后面拼上 `flow.py 上下文` 的上下文包（目标、交接、变更、状态、上游交付、相关决议、该角色的协议切片、带完整路径的可复制命令）。成员不用再读 PROGRESS 和整份协议。
- **身份**：子进程带环境变量 `COLLAB_ACTOR`（成员派活名）、`COLLAB_RUN`（派活编号）、`COLLAB_FLOW`（flow.py 路径），成员调 `flow.py 记` 时自动带上身份和派活编号。
- **结束后**：写一条「进展」（会话、结果）；成员这一轮没写交付、确认、上报或转交，就代写「上报 → 总管：未声明结果」，附最后回复摘要。
- **Claude 命令行成员**：自动加 `--setting-sources local --settings '{"autoMemoryEnabled":false}'`，不带总裁的全局 CLAUDE.md、项目 hook 和自动记忆（11-01 实测有效）。

旧结构项目照旧走下面三道关。

## 派活前的三道关（旧结构项目）

| 关 | 检查什么 | 不过时 |
|---|---|---|
| 1. 校验 | `core/check.py` 查整个 `collab/`：编号、卡头、流转、PROGRESS 表与卡片一致、批准记录、「待你决定」格式 | 不派。确是校验器误报才加 `--skip-check "理由"` |
| 2. 硬性条件 | 有任务卡；卡没通过或归档；属于目标的，目标「进行中」且卡头有「批准：总裁 …」；零散任务有总裁批准记录（流转里经办人「总裁」的一行，或卡头「批准」） | 不派，**不能跳过**。没有任务卡的临时派活加 `--adhoc "理由"` |
| 3. 流程 | 属于目标的：前面的阶段都已通过；席位是该阶段的席位或「验收」；成员与流程表「人选」和卡头一致。零散任务：席位「执行」「验收」的成员与卡头一致 | 不派。确需偏离（例如流程里的人暂时用不了）加 `--override "理由"` |

成员名按班子配置里的「派活名」「别名」在「人选」「执行」「验收」里认，不分大小写；写「—」或空着不检查。

`--adhoc` 只用于旧结构项目，新结构没有临时派活。`--skip-check`、`--adhoc`、`--override` 的理由都记入运行记录的 `override`，偏离项记入 `deviations`，看板标为「偏离」。改流程本身（增删阶段、跳过验收等）要总裁批准，不靠这些参数。`continue` 沿用原派活的 `--adhoc`；朝会只过第 1 关。

## 朝会（meet）

### 新结构项目（有 `collab/内部/流转/`，方案 03）

总管用一条命令搭会议室，总裁进页面直接 @ 就行；也可分步用 flow 建、总裁在页面点「开始讨论」。

```sh
python3 core/dispatch.py room --标题 "…" --依据 "总裁原话" --与会 claude-sonnet:视角 deepseek:视角 --问题 "第一行\n第二行" --开场 "…" [--目标 G001] [--port 3100]  # --问题、--开场 里的 \n 算换行
python3 core/dispatch.py ready I003                # 起草中的议题重做启动检查，就绪就进讨论中
python3 core/dispatch.py check claude-sonnet       # 单独做启动检查（一次最小的真实调用，不写运行记录）
python3 core/dispatch.py meet I003 --wake codex    # 叫醒指定的人（总管按总裁的要求拉人）
python3 core/dispatch.py meet I003                 # 叫醒还没开过口的与会者
```

- **到场**：`room` 建议题，把「问题」和「开场约定」写进议题卡（开场约定进成员的上下文包，软约定），并行做启动检查（结果写 `内部/运行记录/I003.到场.txt` 和一条进展），全部就绪才记总裁的「开始」（总管代记）；成员不抢先发言，等总裁 @。
- **启动环境**：取登录 shell 的 PATH（不写死 nvm 版本，补 Homebrew），去掉 `ANTHROPIC_*`、`CLAUDE_CODE_*`、`CLAUDECODE` 等桌面版带来的变量；朝会、普通派活、启动检查走同一处（`member_env`）。
- **一次叫醒一人**：每位与会者一个 `meet-run` 进程，持有 `内部/运行记录/.朝会-I003-成员.lock`，同一成员同一议题同时只跑一次；没有要它开口的（上次之后总裁没有公开点名它）就不调用模型，上次失败的除外（补叫）。派活编号如 `I003-01`，席位记为「与会」。
- **只喂增量，失败不推进**：只有成功写进黑板的运行才把「读到」记进运行记录；失败、被停止的不算，下次叫它时从上次成功的位置补，启动语里写明上次没成功。第一次发言：叫醒它的那句话和之前的全部公开发言（不含私下），之后的不给；上次没跑成（补叫、收尾）时再加这句话之后的公开发言，只去掉和它同一句话叫来的人的（他们的回答下一轮才给），补过的记在运行记录「补到」，下一轮不重复；之后：上次之后的新发言，不含自己的和私下的。
- **会话丢失**：续接报「No conversation found」这类错时，页面显示原话，运行记录标「会话丢失」，这个会话不再续接；下次叫它（补叫或 @）开新会话，带上到现在的全部公开发言，包括它自己说过的。其他命令行的说法写在 `SESSION_LOST`，只有 Claude 的实测过。
- **会话复用**：挂目标的议题续接该成员在本目标里最近一个正常结束或被停止的会话，失败的不接；项目级议题只续接本议题的；验收席的会话不续接；那个会话还在跑就开新的。
- **写回黑板**：成员不用跑命令。跑完后由 `flow.issue_end` 把最后回复拆成消息写进 `collab/内部/流转/I003.jsonl`：`<私下 总裁>…</私下>` 各成一条私下发言，其余一条公开发言，只回 `[PASS]` 记 PASS；讨论已结束时写入被拒，原文留在运行记录。
- **状态和正在写的内容**：Claude 成员自动加 `--include-partial-messages`。运行记录里有 `phase`（启动中 / 思考 / 调用工具 / 正在写回复）、`last_action`、`steps`、`tokens`（每条助手消息后更新，`result` 到了换成权威数字）；正在写的内容实时写到 `<派活编号>.draft.txt`，结束后删掉，由正式发言取代。看板据此显示：启动中、思考、调用工具、正在写回复、疑似卡住（运行中超过 90 秒没有实际输出，工具运行时命令行发的心跳不算）、失败、已停止，以及已用时间；有人在跑时朝会页约每秒刷新。dsh、codex 没有片段输出，只显示状态、最近动作和（有的话）用量，不显示正在写的内容。
- **停止和收尾**：`dispatch stop-member I003 成员` 停掉这位成员在议题上的运行（会话保留，可补叫）；`dispatch wrap I003 成员` 先停止、再续接同一会话，提示「不要再调用工具，用已有内容发言」，并带上从上次成功的「读到」起的新发言（运行中的追问、被停的那次的问题都在里面），收尾那一次自己也有上限（3 步、4 分钟）。一次收尾只算一次：已经在收尾、或已经发过言没有在跑的，再点什么都不做。页面上的「停止」「让它收尾」调用这两条。
- **运行上限**：每次运行默认 40 步或 10 分钟，到了就停掉并自动续接同一会话收尾，议题里留一条进展写明原因。配置在班子.json：顶层 `"朝会运行上限": {"步数": 40, "分钟": 10}`，成员自己的 `"运行上限"` 覆盖它，写 0 表示不限。不按金额算。
- **只有总裁的 @ 能叫醒人**：成员写的 @ 是普通文字，不记点名、不接力；总裁私下发言里的 @ 也不叫人。成员跑的时候总裁又公开点名了它，跑完再叫醒它自己。
- 对议题用 `start` 会提示改用 `meet`。

## 运行记录格式

每次派活在 `collab/内部/运行记录/` 下留：

- `<编号>.json`：摘要，看板只读这个；
- `<编号>.stream.jsonl`：成员命令行输出的原始事件流（旧记录叫 `<编号>.jsonl`；和 `collab/内部/流转/` 的流转事件不是一回事）；
- `<编号>.err`：标准错误（为空时删除）。

编号是「任务编号-两位序号」，如 `G003-T1-02`（旧任务如 `T003-02`）。`.json` 字段：

| 字段 | 含义 |
|---|---|
| `run` `task` `seat` `member` | 编号、任务、席位、成员 |
| `mode` | 新会话 / 续接 |
| `session` | 成员原生会话 ID |
| `continues` | 续接自哪次派活 |
| `prompt` | 启动语 |
| `status` | 运行中 / 完成 / 失败 / 已中断；看板和 `list` 发现「运行中」但进程已不在时显示为「异常结束」 |
| `started` `ended` `last_at` | 开始、结束、最近一次收到事件的时间 |
| `steps` `last_action` | 工具调用次数、最近一次动作（如“运行：pytest”） |
| `final` `error` `exit_code` | 最终回复、错误、退出码 |
| `override` `deviations` | 偏离理由、偏离项（符合流程时为空） |
| `tokens` | 这次派活的用量汇总：`input`（未走缓存的输入）、`cached`（缓存读取）、`output`、`total`、`calls`（模型调用次数）、`context`（最后一次调用的上下文大小）、`cost_usd`（Claude 命令行给出时）；Codex 另记 `session_cum`（会话累计，续接时用来扣减）。派活时边跑边算，算错只缺这一项，不影响派活 |
| `pid` `child_pid` | 脚本和成员进程号，停止时用 |

运行中每 5 秒最多写一次摘要，这就是看板上的"心跳"。记录只由脚本写，不要手改；不需要时可以整个目录删掉。
