# focus 对照

English: [README.en.md](README.en.md)

把安排里排的计划和专注应用记下的实际放在一起看。需要启用 `schedule`（读它提供的 `plan`，含 `归档/` 里的过去月份）。不写任何数据，也不改实际记录。

- 「对照」页：不进标签栏，从「今天」状态行的链接或 `#对照` 地址打开。近 7 天每天的计划、实际两根条和完成度，点开看按活动的明细；本周分类占比对照周预算；导出文件的新旧。
- 「今天」页：`today.top` 一行"计划 · 已做 · 完成 · 对照 →"；时间轴右边一条实际轨道（`schedule.timeline.lanes`），正在计时的那段画虚线。

## 配置

`config.json` 里 `modules` 加上 `focus`（`init.sh module enable focus`），再加一节：

```json
"focus": {
  "file": "导出文件路径，相对 NOW 数据目录或绝对路径",
  "folder_map": {"应用里的文件夹名": "NOW 的分类名"},
  "budgets": {"工作": ">=25", "项目": "25-30", "学习": "<=30"},
  "week_start": "mon"
}
```

| 配置项 | 含义 |
|---|---|
| `file` | 导出文件。没写或文件不存在时，「今天」页不显示对照内容和链接，直接打开 `#对照` 只有一行说明 |
| `folder_map` | 文件夹名和分类名不一样时写对应，一样就不用写 |
| `budgets` | 每个分类的周占比预算（%）：`>=25`、`<=30`、`25-30`；没写的分类只显示占比 |
| `week_start` | `mon` 或 `sun`，默认 `mon` |

## 导出文件格式

任何工具产出同样格式的文件都能接进来：

```json
{
  "format": "work-rhythm.focus",
  "version": 1,
  "generated_at": "2026-03-04T15:00:00+08:00",
  "records": [
    {"activity": "数学", "folder": "学期课程", "start": "2026-03-03T09:00:00+08:00", "end": "2026-03-03T10:00:00+08:00"}
  ],
  "active": {"activity": "代码", "folder": "项目", "start": "2026-03-04T14:30:00+08:00"}
}
```

时间写带时区的本地时间，按写的钟面时间算；`active` 是正在计时的那段，没有时写 `null`，计时期间至少每几分钟更新一次文件（超过 5 分钟没更新就当计时已断，那段只算到 `generated_at`）；跨午夜的记录按日期切开。`folder` 没有时算"未分类"。`format` 或 `version` 对不上时只显示说明，不计算。

## 怎么算

计划取 `分类（活动）`，没有括号时活动就是分类本身。只有 `HH:MM–HH:MM` 的行算分钟；不计时、备注、全天行不算；只写时间段名或只写开始时间的行是"未定量计划"，显示条数，不进完成度。

先按活动名对（不管空格和大小写）；只写了分类的计划行，再收同分类里没被计划点名的活动；其余都是计划外。写了具体活动的计划不会被同分类的其他活动抵掉，这样"总量对、科目错"能看出来。

| 指标 | 定义 |
|---|---|
| 完成度 | 每个活动 min(实际, 计划) 之和 ÷ 计划量 |
| 计划外 | 每个活动 max(0, 实际 − 计划) 之和 |
| 周占比 | 本周各分类实际量占全部实际量的比例 |

`sample/` 是一份虚构的安排、归档和导出，`tests/test_focus.py` 的期望值就按它手算，`today` 取 2026-03-04。
