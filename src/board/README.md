# 看板网页服务

English: [README.en.md](README.en.md)

一个本地网页，本机所有项目共用一个服务（默认端口 3100），不用每个项目各起一个：

- **首页**（`/`）：没启用 NOW 时是项目列表，列出项目登记表（工具包旁边的 `projects.json`，`init.sh new` 自动登记）里的项目；启用了 NOW 时是 NOW 页，项目列表另在 `/projects`。
- **NOW 页**（`/`）：每次打开都调用本仓库 `board/now/build.py`（`--now-dir` 指向 NOW 数据目录）当场生成，不另写解析，生成结果只放临时目录；各 Markdown 和 `config.json` 里 `output` 指向的静态文件都不改。NOW 目录只放数据，代码不再复制过去，改样式改模板里的 `template.html`。桌面静态 `看板.html` 和 Stop hook 已于 2026-10-22 停用，这一页就是 NOW 看板；手动运行 `build.py --now-dir <NOW 目录>` 仍能出静态文件（现在生成到 `NOW/备份/看板.html`）。额外做了三件事：有 `collab/` 的任务，点标题进项目看板，标题后的小按钮「文档」用默认应用打开它的 `PROGRESS.md`；点 Markdown 链接用系统默认应用打开；页面不整页刷新，Mac 上的数据变了自动更新（见下文「数据接口和推送」）。
- **御前看板**（`/p/<项目>`）：上面是总览，下面用选择器一次只呈现一个板块，不再把所有目标、议题、任务从上到下铺开——
  - 顶部摘要：在推进的目标数、待你决定数、各状态任务数、是否有派活在跑、派活次数和 token 合计。
  - 校验：`core/check.py` 只有提醒时收成一行「校验：N 个提醒」，点开看；有错误时出现标红的「校验」卡，写明文件和行号。有错误时派活脚本不派活，Claude 每轮结束也会被要求先改好。
  - 第一屏：左边「待你决定」，一直显示，没有时只一行小字（按「编号｜类型：要决定什么｜选项与代价｜总管建议｜验收意见｜提出者」拆成小卡，标出总管建议，编号可点，点了切到对应目标或议题）；右边「现在」（每个在推进的目标一句"等谁做什么"，下面是 ▶ 下一步，现状只露 3 行）。有派活在跑时，下面单独出现「正在运行」。
  - 选择器：「目标」一组，每个目标一个按钮（在推进的按「有待你决定 > 受阻 > 进行中 > 待批准 > 暂停」再按优先排，已完成的排后面），带状态和待你决定 / 受阻提醒；「其他」一组是想法（有起草中带阶段的目标时才出现）、零散任务（有不属于目标的任务时才出现）、议题（朝会）、决议。起草中的目标不在「目标」一组里，只在「想法」页：按想法、讨论、方案三组，每行一个目标，带「讨论.md」「方案.md」链接（文件在 `collab/目标/G00x/`，归档后在 `归档/目标/G00x/`，链接跟着走）；目标页和归档页的目标头部也有这两个链接。选中的写在地址栏（`#G00x`、`#issues`、`#dec`、`#loose`），可直接链接；默认选排第一的目标。
  - 主区（选中一个目标）：卡头是编号、标题、状态、阶段进度和派活 token，下面一句"等谁做什么"和「看框架和偏离」；新结构项目上面是关系图（现在）、下面是时序图（过程），旧项目画泳道；最下面「任务」「派活记录」两个标签，只列这个目标的。
  - 泳道流程图（旧结构项目）：按席位分道（总裁 / 总管 / 执行 / 第三方验收，只有出现第三方验收时才有那一道），执行按同一阶段里并行的任务分子道，从上到下是时间，按页面宽度铺开；数据来自目标卡流程表和各任务卡「流转」。浅绿完成、浅红受阻或需补充、黄色是现在所在、虚线是还没到的阶段；点格子看那一步的说明和该任务各次派活的用时、token。「看框架和偏离」展开流程表和偏离记录。
  - 任务：按状态分组的列表（空组不显示），一行一个任务，点开在下面看流转和派活记录。任务编号 `G00x-Tn` 和旧的 `T00x` 都认。
  - 派活记录：按开始日期分组（新的在上，组头写当天次数、合计用时和 token），列为派活、任务、席位·成员、状态、开始、用时、token、结果（去掉 Markdown 符号，最多两行）；点一行看启动语、token 明细和最终回复。
  - 主区（选中议题）：新结构项目只放结论——每个议题一张卡，状态、类型（朝会 / 会审）、所属目标、与会和视角、发言数、最近一条（私下的不露内容）、谁在思考，以及总结（共识、方案、总管建议）和裁决；「进入朝会 →」打开对话页。旧结构项目照旧显示 第1轮 → 第2轮 → 总结 → 裁决 的进度，点开按轮看发言原文。待裁决的标黄，选择器上也提示。
  - 选中目标时，时序图里每个挂在它上面的议题是一行折叠框（在议题开始的位置，如框架会审在「提交」和「批准」之间），点开进对话页；时序图下面列出挂着的议题。
- **朝会页**（`/p/<项目>/meet/<议题>`，新结构项目）：群聊式。左栏是本项目的议题（状态、最近一条或谁在思考），右边是对话：总裁的气泡在右、成员在左，发言类型（立场、提问、回答、补充、私下、PASS，由投影推出）是小标签，私下是虚线黄底，开始、结束、总结、裁决是居中的小标签，总结和裁决单独成卡；被叫醒的成员显示「正在思考」，派活失败也会提示。输入框打 `@` 弹出与会者菜单，下面实时提示「会叫醒 …」；「私」切换私下（只有总管能看到，不叫醒人）；回车发送。按钮随状态变：起草时「开始讨论」，讨论中「结束讨论」，收口中「继续讨论」，待裁决时在输入框写裁决（原话记作依据）点「裁决」。推送更新（见下文「其余页面推送更新」），有成员在跑时发言的流式输出最多每 10 秒刷新一次；窄屏只留对话区。数据来自 `GET /api/p/<项目>/meet/<议题>`（视图模型里的议题 + 运行记录）。
- **NOW 页的朝会入口**：右下角列出各新结构项目里讨论中、收口中、待裁决的议题（`GET /api/meetings`，只读聚合），点进对话页；没有就不显示。
  - 主区（选中决议）：生效决议列表。
  - 推送更新：本项目账本变了才拉数据重画，保留选中的目标、展开状态和滚动（见下文「其余页面推送更新」）。
  - 用 `--override` 派的活在目标、任务卡和派活记录上都标「偏离」，点开看理由。
  - 顶部标题行有「已归档 N 个目标、N 张任务 →」链接（有归档时才出现），通往归档页；目标流程表里已归档的子任务也链到归档页对应任务。
  - NOW 页任务标题后显示摘要，如「G001 ②/5 · I001 待裁决」（点了也进看板），有受阻的标黄。

- **班子页**（`/team`，NOW 页右下角和项目看板右上角有入口）：方案 05，只展示个体，不画结构——
  - 一人一张名片：头像（名字缩写，颜色按应用区分）、名字、应用和派活名，右上角是状态（在跑 / 手里 N 件 / 空闲 / 不可用）；下面一句擅长，三格数字（能力档、各项目合计的派活次数、token），能坐的席位（执行、确认、第三方验收、与会，按「常坐席位」「职能」推出），手上的活（在跑的派活和新结构项目里持有人是他的任务，点项目名进项目看板），「档案」默认收起（型号、相对成本、不适合、职能）。
  - 档案来自班子目录（环境变量 `COLLAB_TEAM`；没设时用工具包旁边的 `班子/`，本机发布后即 `NOW/班子/`；都没有时 `~/.collab-team`）里的 `班子.json`，「待填」的灰显。
  - 推送更新（班子配置或任一项目账本变了才拉）。和其他页一样只读，改班子仍然只改 `班子.json`。

- **人才市场**（`/talent`，规划中，和班子页互相有入口）：按身份列出人才——技能、擅长、可由哪些成员扮演（已在班子里的标「在班子」）；点技能只看有这项技能的身份。读静态的 `~/.collab-team/人才.json`，没有时显示工具包示例 `core/team-example/人才.json` 并标「示例」；打开时读一次。

- **归档页**（`/p/<项目>/archive`）：只看 `归档.md` 或 `归档/目标/`、`归档/任务/`、`归档/议题/` 里的卡，和项目页分开。归档目标一行一个，点一行看它的泳道流程图（降低饱和度）和「看框架和偏离」；归档任务按所属目标分组，零散任务单列，点开看流转和派活记录；归档议题可看各轮发言和裁决。只在打开时加载一次，不连推送、不轮询；地址栏 `#G00x` 选目标、`#G00x-Tn` / `#T00x` 直接展开任务。被取代的决议暂不显示。

第一版不显示成员的对话过程；需要时去 Codex 回看看板或 dsh web 看。

## 启动

在项目根目录执行：

```sh
python3 board/server.py
```

打开 http://127.0.0.1:3100

| 参数 | 作用 |
|---|---|
| `--port` | 端口，默认 3100 |
| `--now-dir` | NOW 数据目录（Markdown 和 `config.json`），默认环境变量 `COLLAB_NOW_DIR`，没有时：工具包发布在 NOW 目录下（`NOW/系统/`）就用它的上一级，其次 `NOW_PATH`；都没有就不启用 NOW，首页（`/`）是项目列表，有 NOW 时项目列表在 `/projects`；生成代码在 `board/now/` |
| `--project <目录>` | 额外显示一个不在 NOW 里的项目，可重复 |

## 静态导出

不起服务也能看一个项目的看板（只读），比如放到 GitHub Pages：

```sh
python3 board/export_static.py --project <项目目录> --out <输出目录> [--id 15730301] [--team <班子目录>]
```

导出项目页、归档页、每个议题的朝会页、班子页，以及它们要的数据（`api/…json`，和本机服务 `/api` 是同一套函数现算的同一份）；`collab/`、`work/` 下的文本文件转成只读网页放在 `files/`，看板里的文件链接指向它们。页面里写 `window.BOARD_STATIC`（项目、到导出根的相对路径），前端据此读 JSON、把链接改成相对路径、隐藏批红和发言这些写入口、不轮询；本机服务下没有它，行为不变。数据里的项目根和班子目录换掉，导出后再扫一遍，还有本机路径就报错。演示案例的八回网站由 `demo/site.py` 调它生成。

## 常驻运行

常驻由两部分组成：一个「御前看板」小应用，和 launchd 用户代理。小应用只负责反复启动 `server.py`（服务退出 3 秒后重启），并持有 macOS 的「文稿」访问权；launchd 负责登录后自动启动它、它退出后拉起。

> 为什么不用 launchd 直接启动 Python：实测 launchd 启动的 `/usr/bin/python3` 读 `~/Documents` 会被 macOS 隐私保护拦成 `Operation not permitted`，而且不会弹授权窗口。让应用由系统正常启动一次、总裁点「允许」后，它启动的 Python 子进程继承授权，不需要「完全磁盘访问」。

```sh
bash board/build_app.sh          # 可选：只重建应用，不安装
bash board/service.sh install    # 装应用到 ~/Applications、写 plist、启用
bash board/service.sh status     # 应用 / launchd / 启动器 / 服务 / 接口 / 最近日志
bash board/service.sh restart
bash board/service.sh logs       # logs -f 跟踪，logs 200 看最后 200 行
bash board/service.sh uninstall  # 停用、删 plist/应用/配置，日志保留
bash board/service.sh remote on  # 经 Tailscale 让自己的手机、iPad 访问（remote off 关，remote status 看）
```

`install` 会做四件事：

1. 生成（或复用）`board/build/御前看板.app`，拷贝到 `~/Applications/御前看板.app`；
2. 用 `open` 启动应用做一次权限检查——**首次会弹「御前看板想访问文稿文件夹」，请点「允许」**；
3. 停掉 3100 上手动启动的同一个看板进程（其他进程不动）；
4. 写 `~/Library/LaunchAgents/com.local.ai-company-board.plist` 并加载，等接口通。

| 内容 | 位置 |
|---|---|
| 应用 | `~/Applications/御前看板.app` |
| 配置 | `~/Library/Application Support/ai-company-board/config`（SERVER / PORT / NOW_DIR / LOG_DIR） |
| launchd 代理 | `~/Library/LaunchAgents/com.local.ai-company-board.plist` |
| 启动器日志 | `~/Library/Logs/ai-company-board/launcher.log`、`launcher.err.log` |
| 服务日志 | `~/Library/Logs/ai-company-board/board.log`、`board.err.log` |

- 端口默认 3100，安装时可用 `BOARD_PORT=3200 bash board/service.sh install` 改；NOW 目录可用 `BOARD_NOW_DIR=...` 指定；不指定时用工具包旁边的 NOW 或已安装配置里的值，都没有就不启用 NOW（照样能装，首页是项目列表）。改过的值写进配置，之后 `status` / `restart` 以配置为准。
- 只监听 `127.0.0.1`。`KeepAlive` 为真：杀启动器约 5 秒后由 launchd 拉起；杀 Python 由启动器 3 秒后拉起。
- 改 `server.py` 不需要重建应用；应用里只放启动器，每次启动都读取配置里的 `SERVER`，指向当前的 `board/server.py`。项目目录移动后重跑 `install` 会重写配置，应用不用重建。只有改 `launcher.c` / `build_app.sh` 后 `install` 才重建；重建后签名会变，系统可能再问一次「文稿」。
- `build_app.sh` 会做 `plutil -lint` 和 `codesign --verify --deep --strict`；应用是 ad-hoc 签名，不需要开发者证书。
- `install` 要在普通 Terminal 里跑；受限沙箱可能不能写 `~/Library`、`~/Applications`。
- `uninstall` 会删应用、配置和 plist，但 macOS 里给「御前看板」的「文稿」授权还在；要彻底清掉，去 系统设置 → 隐私与安全性 → 文件与文件夹 删除「御前看板」。

### 在手机、iPad 上看（远程访问）

服务只监听 `127.0.0.1`，同一 Wi‑Fi 里的其他设备连不上，这是有意的：看板没有登录，能批准、能在朝会里发言。要在自己的其他设备上用，走 [Tailscale](https://tailscale.com/download) 私网：

1. Mac 和手机都装 Tailscale，用同一个账号登录（Mac 也可从 App Store 装）。
2. `bash board/service.sh remote on`：用 `tailscale serve` 把 `https://<本机名>.<tailnet>.ts.net` 代理到本机端口，打印出地址。第一次用时 Tailscale 会提示在后台开启 HTTPS，照提示开一下再运行一次。
3. 手机打开那个地址。校园网、家里 Wi‑Fi、蜂窝流量都能连，只有你 Tailscale 里的设备能打开。

- 看到的是 Mac 上的实时数据，批准、朝会发言照常可用；「打开文件」在远程端不显示，服务端也拒绝（文件在 Mac 上）。经代理来的请求（带 Tailscale 或 X-Forwarded 头，或 Host 不是本机名）算远程。
- Mac 要开着、不睡眠，合盖或睡眠时手机打不开。
- 不要用 `tailscale funnel`，那会把看板放到公网。`remote off` 关掉代理。

### 权限问题排查

1. `bash board/service.sh status`，看「应用」「启动器」「服务进程」「接口」和最近日志。
2. 日志里出现 `Operation not permitted`：
   - 安装时没点「允许」：先 `open -a ~/Applications/御前看板.app` 触发弹窗并点允许，等几秒后重跑 `bash board/service.sh install`（会先停掉这个手动实例）。
   - 已点过拒绝：系统设置 → 隐私与安全性 → 文件与文件夹 → 御前看板 → 打开「文稿文件夹」。
   - 仍不行：`service.sh uninstall` 后重装，让系统重新询问。
3. 端口被别的程序占用：看 `lsof -nP -iTCP:3100 -sTCP:LISTEN`；`install` 只停本看板的 `server.py`，不会杀其他进程。
4. 只想临时看一次：`python3 board/server.py`，用完 Ctrl+C；会影响常驻服务时先 `service.sh uninstall`，看完再 install。

## 数据从哪里来

有 `collab/内部/流转/` 的新结构项目，目标、任务的状态、持有人、阶段、待你决定和校验结果都取自 [`flow.py`](../core/flow.py) 的视图模型，卡片只提供标题和手写字段；目标区上面画**关系图**：总裁在左、总管居中（每件在办的差事一个带状态的端口）、成员在右（按参与者顺序固定位置，名字、手里的差事、已持有多久），每件没结束的差事一条边从交过来的人指向现在的持有人，实线派出去、虚线交回来，颜色是状态（绿在办、黄待确认、红受阻或未通过、灰待派或暂停），成员之间的交接画成卡片右侧的弧线，底部一行是最近一次交接；点差事时序图只看它并滚到它的最新一步，点时序图上的箭头关系图回放到那一刻（「回到现在」退出）。演示案例有 `collab/内部/流程/时钟.json` 时「多久前」「已持有」按它算。下面画**时序图**（不再画泳道）：一条生命线一个参与者（按计划人选排，未出场的置灰），从上到下按项目序每条事件一格，主干实线、支线虚线，持有期画成生命线上的粗条，已通过的阶段折叠成一行（点一行展开，图例右边「全部展开 / 全部折叠」一次切换），长间隔画成折断；点箭头看说明、证据、会话、用时和 token，点任务只看它。不属于目标的任务在选择器的「零散任务」里，同样画时序图。看板只画视图模型，不读事件、不推断。

旧结构项目照旧读 Markdown，来源如下：

| 内容 | 来源 |
|---|---|
| 项目列表 | 项目登记表 `projects.json`，NOW.md「任务」表和 `NOW/已完成.md` 里链接到 `collab/PROGRESS.md` 的行（启用了 NOW 时），加 `--project`；按项目根目录去重 |
| 下一步、现状、决议、待你决定 | 项目 `collab/PROGRESS.md` |
| 目标卡 | `collab/目标/G*.md`（旧的小版本项目读 `collab/目标.md`），含归档；卡头「状态」和「流程」表 |

只读，加只能追加经过校验的黑板事件：不直接写任何项目文件。动作只有两个，都要求请求头 `X-Board: 1`：`POST /api/open` 用 `open` 打开家目录下的文件（限 Markdown、文本、网页、图片、PDF 等）；`POST /api/p/<项目>/meet/<议题>` 是朝会页的受限写入口，只接受总裁的发言（含 @ 和私下）、开始讨论、结束讨论、继续讨论、裁决、取消，经 `flow.record` 走和命令行同一套检查写一条事件，不合法原样返回错误；带 @ 的发言和「开始」再在后台跑 `dispatch.py meet --detach` 叫醒相关成员。只监听 `127.0.0.1`，只用 Python 标准库。

**数据接口和推送**：NOW 数据另有 `GET /api/now`（即 `now/build.py` 的 `data()`：不含模块 css、js，带外壳指纹 `shell`；外壳是 `shell()`，模板加模块 css/js 和语言包，数据留空；`python3 build.py` 生成的独立文件仍是外壳加内嵌数据）。NOW 页、`/api/now`、`/api/p/<项目>`、朝会、`/api/projects`、`/api/meetings`、`/api/team` 按依赖文件的指纹（路径、修改时间、大小）缓存，文件没变不重算（命中约 3ms），但缓存最长留 60 秒（有的数据来自依赖清单以外，如专注计时、成员进程还在不在）；同一块同时来的请求只算一次；ETag 不算生成时间，前端带 `If-None-Match` 就回 304。项目分两类版本：账本 `p:<项目>`（`collab/` 去掉 `internal/runs/`：流转事件、卡片、PROGRESS、决议，朝会的黑板也在里面），变了马上推、马上重算；运行 `r:<项目>`（`internal/runs/` 下的运行流和运行记录，成员在跑时每秒都在写），推送和重算都最多每 10 秒一次，期间回上次结果。服务里有一个监视线程，每秒 stat 一遍各块的依赖（`now`：NOW 的依赖清单；`p:<项目>`、`r:<项目>`；`team`：班子和人才配置；`shell`：外壳和 `static/`），不执行模块的 `load.py`，单轮超过 20ms 降到 2 秒一轮；哪块变了版本号就加一（`shell` 的值是外壳指纹）。根路径的 `/apple-touch-icon*.png`（iOS 加到主屏、打开主屏 app 时会去找）给 180 图标，`/favicon.ico` 给 192 图标。`GET /api/events` 是 SSE：连上先推一次全部版本号，之后有变化推 `event: change`（内容是全部版本号），每 15 秒一行心跳注释，最多 16 个连接；`GET /api/versions` 是推送不通时的短轮询。

**NOW 页按需重画**：`/` 给的是外壳（不含数据，带外壳指纹 `<meta name="board-shell">`），页面打开后拉 `/api/now` 再画；之后订阅 `/api/events`，`now` 的版本号变了只拉数据、在本地重画，保留当前标签、滚动位置和展开的卡片；输入框有焦点、正选着文字或刚点按时推迟到空下来再画。前端自己记 ETag 和版本号，版本号没变不请求；切回前台重连并补拉一次，在前台时每 5 分钟也补拉一次（没变就是 304）；任务旁的项目摘要和朝会入口只看账本 `p:*`、不看运行 `r:*`，最多每 60 秒拉一次（期间的多次变化合并，切回前台也受这个限制，在后台到点不拉）；外壳指纹变了（发布了新代码）才整页重载一次。右下角标出实时 / 连接中 / 离线 · 截至 HH:MM。推送封装在 `static/live.js`（`BoardLive.start({watch, onChange, onResume})`），各页共用。`python3 build.py` 生成的独立文件仍内嵌数据，直接打开就画，不连推送。

**其余页面推送更新**：项目页和朝会页看块 `p:<项目>`、`r:<项目>`，班子页看 `team` 和各 `p:*`、`r:*`，人才页看 `team`；收到本页的块变了才拉数据，另有前台 60 秒保底和切回前台补拉。数据请求用 `BoardLive.getJSON()` 自己带 `If-None-Match`（不靠浏览器 HTTP 缓存），没变回 304、不重画；`/api/p/<项目>`、朝会和人才接口带 `X-Board-Version`（项目和朝会另带运行版本 `X-Board-Run-Version`），页面记下后推送来同一版本就不再拉；拉到的运行版本比推送来的旧（服务端 10 秒内回上次结果）时 10 秒后再拉一次。朝会页有成员在跑时不再每秒拉，流式输出跟着 `r:<项目>` 的推送最多每 10 秒刷新一次。右上角平时显示「推送更新 · 时间」，断线时前面加「连接中 / 离线 · 截至 HH:MM」。静态导出（`export_static.py`）的页面去掉 `live.js`，和归档页一样只加载一次，不连推送、不轮询。

**主屏 app 和离线**：各页（NOW、项目、朝会、班子、人才）头部带 `manifest`（`/manifest.webmanifest`，全屏 `standalone`）、`apple-touch-icon`（180×180）、`apple-mobile-web-app-capable` 和 `viewport-fit=cover`，Safari「分享 → 添加到主屏幕」后点图标全屏打开 NOW 页。`static/pwa.js` 注册根路径的 Service Worker `/sw.js`（服务端把当前外壳指纹填进去）：页面外壳和 `static/` 文件先用本地缓存、后台再更新，缓存名带外壳指纹，发布新代码后新版 SW 立即接管（`skipWaiting` + `clients.claim`）、删掉旧缓存，页面整页重载一次拿到新代码；`GET /api/…` 先走网络，成功存一份，连不上 Mac 时回退上次的数据，响应头 `X-Board-Cache: offline`、`X-Board-Cached-At` 标明是缓存，页面据此显示「离线 · 截至 HH:MM」，Mac 回来后自动转实时并追上。写操作（`POST`）、`/api/events`、`/api/versions` 不经缓存；离线时批红、意见、朝会发言置灰，底部提示「离线，连上 Mac 后再操作」。Service Worker 只在 HTTPS 或本机（127.0.0.1、localhost）下可用：`tailscale serve` 给的 `https://<机器名>.<tailnet>.ts.net` 有离线功能；直接用 Tailscale IP 走 http 时不注册、不报错，其余照常。静态导出不注册。
