# 批红

**AI 票拟，你来批红。**

明朝处理政务有一套分工：内阁先替皇帝拟好处理意见，叫「票拟」；皇帝用朱笔批可否，叫「批红」；六部照批示执行，给事中、御史可以把不妥的诏令退回。这个工具包把这套分工用在 AI 身上：AI 拟方案、做执行、互相把关，你只拿朱笔做决定。

把几个 AI 助手组织成一个小班子，替你推进真实项目。你定目标、拍板；Claude、Codex、DeepSeek 等助手在各自的原生应用里分工执行、互相验收，进度写进项目里的共享文件，在本机看板上一目了然。

全部是本地 Markdown 文件和 Python 标准库脚本，不需要数据库、账号或云服务。

## 为什么做

和 AI 一起做一件持续几周的事，聊天窗口很快就不够用了：

- **上下文散在聊天记录里**：换个会话、换个模型，就要重新交代一遍背景；昨天谈定的事，今天的会话不知道。
- **一个模型包办一切**：自己出方案、自己执行、自己说做完了，没有第二双眼睛。
- **你被拖进细节**：每一步都要盯着，分不清哪些事真正需要你拍板。
- **做到哪儿了说不清**：进度、卡点、花了多少 token，只能翻聊天记录。

这个工具包的做法是：**按「项目 → 目标 → 任务」组织工作，而不是按聊天组织工作**，把上下文放进项目目录里所有助手都能读写的文件，再用规则和脚本让多个模型按分工协作。

## 好处

### 1. 围绕项目、目标、任务对话，而不是围绕聊天

每个项目有一个 `collab/PROGRESS.md` 作为唯一入口，写着现状、决议和「▶ 下一步」。工作拆成三层：

- **项目**：一个目录，一份 `PROGRESS.md`。
- **目标**（`G001`）：你要的结果、成功标准，以及你批准的流程，即分几个阶段、每个阶段谁做、谁验收。
- **任务**（`G001-T1`）：一张卡写清目的、交付、授权边界、什么情况要上报，流转表记录每次交接。

任何会话开工时先读 `PROGRESS.md`，从「▶ 下一步」接着做。对话随时可以关掉，工作不会丢。

### 2. 共享的工作台上下文

协作文件都放在项目的 `collab/` 文件夹里，项目根目录只多一个 `AGENTS.md`，Claude Code 通过 `.claude/CLAUDE.md` 导入同一份。Claude、Codex、DeepSeek 打开同一个项目，看到的是同一套现状、决议和任务卡，换模型不用重新交代背景。

公共文件只写结论和位置，详细的推理和执行过程留在各自的原生会话里，需要时再回看。这些文件是纯 Markdown，可以用 git 管理，内容完全归你，也不绑定任何一家的产品。

### 3. 多模型分工协作

按席位分工，而不是让一个模型包办：

| 席位 | 明朝对应 | 谁来坐 | 做什么 |
|---|---|---|---|
| 总裁 | 皇帝批红 | 你 | 定目标、批准框架、做重大取舍 |
| 总管 | 内阁票拟 | 一个主力助手（如 Claude） | 拆目标、起草流程、派活、协调、整合成果 |
| 执行 | 六部 | 按任务挑选（如 Codex、DeepSeek） | 在授权范围内自主完成任务 |
| 验收 | 给事中封驳 | 总管或第三方模型 | 对照成功标准判断是否达成，不达标就退回返工 |

- **用人所长**：成员表记下每个模型的档位和成本，总管按任务难度选人。
- **交叉验收**：重要目标可以交给另一个模型验收，执行者自己说做完了不算数。
- **朝会**（廷议）：遇到需要讨论的问题，告诉总管，总管搭好会议室、确认成员能启动，你进去 @ 想听的人。同一句话叫醒的人各自独立发言，互相看不到；最后由你裁决。

### 4. 保留原生应用的全部能力

不重写一个 agent。每个成员在自己的命令行工具里运行，比如 Claude Code、Codex CLI、DeepSeek Harness，文件、终端、搜索这些能力都照常可用。派活脚本只负责启动、续接、停止，并记录每次派活。同一个目标里尽量续接已有会话，不必每次从头开始。

### 5. 你只管需要你决定的事

总管的分析和流程框架要你明确同意后才能派活。框架内的问题由总管自己解决，只有真正卡住时才上报。需要你拍板的事统一放在「待你决定」，每条写清类型、可选方案与代价、总管建议和验收意见，你看完就能决定。

### 6. 规则由程序把关，不靠 AI 自觉

- **校验器**（`core/check.py`）：检查卡片格式、状态是否前后一致、编号是否重复、该有的批准记录有没有。
- **没批准不开工**：所有任务都要归属目标；目标没批准、任务还在规划中时不能派发，也不能越过。总管自己动手也一样：没有执行中的任务，它不能改项目文件。
- **派活前把关**：校验出错、交接没写时，脚本直接拒绝派活。偏离你批准的流程时，必须写明理由，看板上会标出「偏离」。
- **每轮结束自动校验**：Claude Code 每轮结束时自动运行校验，有错误就不让这一轮结束，并要求它补全内容，不准删内容或编造批准来通过校验。

### 7. 进度一眼看清

本机常驻一个网页看板（http://127.0.0.1:3100），每次打开都从 Markdown 当场生成：

- **NOW 页**：所有项目、今天的安排、未来 7 天、本月布局。
- **项目看板**：待你决定、时序图（整体流程：阶段、任务、谁交给谁，没发生是灰色，发生后就地变成带时间的实线）和关系图（现在谁手里拿着什么）、任务卡、正在跑的派活、每次派活的用时和 token。开工前就能看图、提意见、改图和批准，开工后能看到实际和批准版的差别。
- **归档页**：已完成的目标和任务，同样可以看时序图、任务卡和记录。

## 和直接聊天的区别

| | 直接聊天 | 本工具包 |
|---|---|---|
| 工作单位 | 一个会话 | 项目 → 目标 → 任务 |
| 上下文在哪 | 聊天记录里 | 项目里的 `collab/` 文件，所有助手共用 |
| 换会话或换模型 | 重新交代背景 | 读 `PROGRESS.md` 接着做 |
| 谁来做 | 一个模型包办 | 按席位分工，按难度和成本选人 |
| 做完了吗 | 模型自己说了算 | 对照成功标准验收，可交给第三方模型 |
| 你的角色 | 盯着每一步 | 批准框架，处理「待你决定」 |
| 规则 | 写在提示词里，靠自觉 | 校验器和派活脚本把关 |
| 进度 | 翻聊天记录 | 看板：流程图、状态、用时、token |

## 适合什么

- 持续几天到几周、需要分阶段推进的事：科研、课程项目、求职准备、写作、做工具。
- 想让多个模型分工、互相检查，而不是只用一个。
- 想把和 AI 合作的过程沉淀成可追溯、可复用的记录。

一次性的小问题直接聊天更快，不必建项目。

## 快速开始

> 目前只在 macOS 上用过；统一的 `collab` 命令还在做。

需要 Python 3（只用标准库），以及至少一个 AI 助手（Claude Code、Codex CLI 等）。

本目录是工具包本身。日常使用的是发布出来的独立拷贝，下文记为 `<工具包>`；它放在 NOW 数据目录里的 `系统/`，班子配置放在旁边的 `班子/`：

```
<NOW 所在目录>/
  NOW.md          总看板
  NOW/            数据：安排、已完成、本月布局、config.json
    系统/         工具包（core/publish.sh 发布，不带 git）
    班子/         班子.json，以后放人才
```

1. 建立 NOW 总看板（`NOW.md` 和 `NOW/` 数据）：

   ```bash
   core/init.sh now <NOW 所在目录>
   ```

2. 把工具包发布进去，并让看板开机常驻：

   ```bash
   core/publish.sh <NOW 所在目录>/NOW/系统
   bash <NOW 所在目录>/NOW/系统/board/service.sh install
   ```

   打开 http://127.0.0.1:3100 ，点项目标题进项目看板。之后改了工具包，提交后再运行一次 `core/publish.sh` 即可，看板会自动重启。

3. 在要推进的项目目录里装上工作台（`AGENTS.md` + `collab/`），项目会自动加进 NOW 的任务表：

   ```bash
   NOW_PATH=<NOW 所在目录>/NOW.md <工具包>/core/init.sh new
   ```

   然后让助手按 `collab/PROGRESS.md` 填好目标、截止日期和「▶ 下一步」。

4. 需要派活给命令行成员时，用派活脚本，见 [core/README.md](core/README.md)「派活」。

init.sh 的全部命令和班子配置见 [core/README.md](core/README.md)「init.sh」，NOW 总看板见 [board/now/README.md](board/now/README.md)，看板常驻见 [board/README.md](board/README.md)。

## 目录

```
core/flow.py           流转的唯一写入口和投影：骨架、事件、检查、生成块、视图模型、上下文包
core/check.py          collab/ 校验：派活前、Claude 每轮结束（Stop hook）、看板顶部都用它
core/collab_parse.py   任务卡、目标卡解析（旧结构项目和卡片手写字段）
core/skeletons/        流程骨架：task、goal（general / research / dev 三种阶段模板）、issue，加载清单 loading，渲染规约 render；history/ 放旧版本
core/dispatch.py       派活：派活、续接、停止、按流程检查、朝会、写运行记录（用法见 core/README.md）
core/init.sh          给项目装工作台、建 NOW、建班子、team-sync、装 hook、register / unregister、管理看板模块、合并口令；core/team.py、core/now_rows.py、core/modules.py 是它的帮手
core/publish.sh       把工具包发布到本机 NOW/系统/；--core 只带核心，--module 单独导出一个模块
core/口令.md          核心的口令，和已启用模块的口令合并成 NOW/口令.md
core/team-example/    班子、人才示例
board/                 看板网页服务：NOW 页、各项目看板和归档页、朝会、班子；board/now/ 是 NOW 看板的核心（「任务」页、模块加载器）和数据样板
modules/               NOW 看板的模块：schedule（今天、短期）、deadlines（近期截止）、focus（计划与实际对照）、calendar（日历），用 init.sh module 按需打开
workbench/             工作台：init.sh new 装进项目的那一套（AGENTS.md、.claude/、collab/）
```
